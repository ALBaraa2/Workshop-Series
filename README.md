# Backend & Software Development Workshops

A series of 5 practical, intermediate-level workshops for people with basic programming/backend knowledge — built for Computer Science / Computer Engineering students and Junior Developers, not absolute beginners.

Each workshop is ~60 minutes, bilingual (**Arabic + English** in the same file), and follows the same format: real examples, Bad vs Good code where relevant, hands-on exercises, and a final challenge.

## Workshops

| # | Title | File | Focus |
|---|---|---|---|
| 1 | Developer Toolkit | [`developer_toolkit_workshop.md`](./developer_toolkit_workshop.md) | Git, GitHub, Postman, ngrok, Vercel, DevTools, Docker — the daily developer workflow, tool by tool, connected in one realistic project scenario |
| 2 | Clean Code | [`clean_code_workshop.md`](./clean_code_workshop.md) | Naming, functions, SRP, DRY/KISS/YAGNI, error handling, code smells, refactoring, SOLID (simplified) |
| 3 | Common Problems in Software Development | [`common_problems_workshop.md`](./common_problems_workshop.md) | N+1 queries, race conditions, poor API design, SQL Injection/XSS/Mass Assignment, Git & team pitfalls — problem → cause → detection → fix → prevention |
| 4 | Software Requirements & SRS | [`srs_workshop.md`](./srs_workshop.md) | Turning a vague client idea into Functional/Non-Functional Requirements, User Stories, Use Cases, and a full SRS document |
| 5 | Agile & Software Team Workflow | [`agile_workflow_workshop.md`](./agile_workflow_workshop.md) | Agile/Scrum in practice, Requirements → Epics → User Stories → Tasks, Git collaboration, Pull Requests, Code Review, team communication, and a full team simulation |

## How the series connects

The workshops build on each other and share one running example project (**Volunteer Management System**, introduced in workshop 4):

```
1. Developer Toolkit  →  the tools you use every day
2. Clean Code          →  how you write the code itself
3. Common Problems     →  what goes wrong if you don't watch for it
4. SRS                 →  how a vague idea becomes a clear requirement
5. Agile Workflow       →  how a team turns that requirement into a shipped feature
```

Workshop 5 reuses the requirements from workshop 4 and the tools from workshop 1, so the series can be delivered as a standalone set or as a connected 5-part program.

## Format of each file

Every workshop file follows the same internal structure:
1. Title, Learning Objectives, Prerequisites, Agenda
2. Introduction
3. Core concepts, explained with real examples
4. Hands-on exercises
5. Final challenge
6. Common mistakes & Best practices
7. Summary, Discussion questions, Additional resources

Each file contains **Part 1 — Arabic** followed by **Part 2 — English**, with identical content, structure, and examples in both languages.

## Audience

Computer Science / Computer Engineering students and Junior Developers with basic programming and backend fundamentals already in place.
